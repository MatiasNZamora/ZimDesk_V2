Qué es Callmebot Gratuito

Callmebot es un servicio gratuito que permite enviar mensajes de WhatsApp mediante una simple petición HTTP GET. No requiere cuenta, tarjeta de crédito ni aprobación de Meta.

⚠️
Cada número de teléfono debe activarse individualmente una sola vez antes de poder recibir mensajes. El límite es aproximadamente 10 mensajes por hora por número.

La API funciona así:

GET https://api.callmebot.com/whatsapp.php?phone=+54911...&text=Mensaje&apikey=123456

Activar Callmebot en cada número

Proceso de activación (una sola vez por número)
Hacé esto para cada persona que quiera recibir alertas — admins y agentes por separado.
1

Guardar el contacto de Callmebot

Desde el teléfono que va a recibir las alertas, guardá este número como contacto:

+34 644 97 83 41
2

Enviar el mensaje de activación

Enviá por WhatsApp al contacto guardado exactamente este texto:

I allow callmebot to send me messages
3

Recibir la API Key

En unos segundos Callmebot responde con tu clave personal, por ejemplo:

Your WhatsApp number +5491112345678 has been registered.
Your API key is: 123456

Guardá ese número de 6 dígitos — lo vas a necesitar en el siguiente paso.

Configurar en ZimDesk

Variables de entorno para admins

Editá el archivo .env.local en la raíz del proyecto y agregá:

# Formato: telefono:apikey separados por coma para múltiples admins
WHATSAPP_ADMIN_RECIPIENTS=+5491112345678:123456,+5491187654321:654321
ℹ️
El teléfono debe incluir el código de país con + y sin espacios. Ejemplo para Argentina: +5491112345678

Reiniciá el servidor de desarrollo para que tome los cambios:

npm run dev

Configurar teléfono de agentes Agentes

A diferencia de los admins (que se configuran por variable de entorno), los agentes guardan su número directamente en su perfil de usuario dentro de la aplicación.

1

Ir a Usuarios en el panel

Entrá como admin y navegá a /users.

2

Editar el agente

Hacé click en "Editar" en el usuario agente correspondiente.

3

Completar los campos de WhatsApp

Al final del formulario aparecen dos campos:

  • Teléfono WhatsApp: número con código de país, ej. +5491112345678
  • API Key Callmebot: el número de 6 dígitos recibido al activar
✅
Si un agente no tiene teléfono configurado, simplemente no recibe WhatsApp. Solo recibirá el email de asignación. No hay error ni fallo.

Probar la integración

Podés verificar que Callmebot funciona con el número antes de configurarlo en la app:

curl "https://api.callmebot.com/whatsapp.php?phone=+5491112345678&text=Hola+desde+ZimDesk&apikey=123456"

Si el mensaje llega al teléfono, la integración está correctamente activada.

Para probar el flujo completo dentro de la app:

  1. Creá un ticket de prueba como usuario cliente
  2. Verificá que llegue el WhatsApp al número configurado en WHATSAPP_ADMIN_RECIPIENTS
  3. Asigná el ticket a un agente con teléfono configurado
  4. Verificá que el agente reciba email + WhatsApp

Cuándo se notifica

🎫 Ticket creado
Se dispara al completar el formulario de nuevo ticket.

Destinatarios: Admins

Canal: Email + WhatsApp

Mensaje WA:

🎫 Nuevo ticket #14
📌 El servidor de archivos no responde
👤 Lucía Fernández
👤 Ticket asignado a agente
Se dispara cuando un admin asigna el ticket a un agente desde el panel de gestión.

Destinatarios: Agente asignado

Canal: Email + WhatsApp (si tiene teléfono configurado)

Mensaje WA:

📋 Te asignaron el ticket #14: "El servidor de archivos no responde"

Dar conformidad Cliente

Cuando un agente marca un ticket como Resuelto, el cliente puede dar su conformidad confirmando que la solución fue satisfactoria. Esto cierra el ticket definitivamente.

¿Cómo funciona?

El cliente accede al ticket y, si está en estado Resuelto, verá dos opciones en el panel de acciones:

  • ✅ Dar conformidad — confirma la solución y cierra el ticket
  • 🔓 Reabrir ticket — si la solución no fue satisfactoria

ℹ️
Al dar conformidad se registra un log en el historial del ticket: "[Cliente] dio conformidad y cerró el ticket." Esto queda visible en el modal de Historial.

Flujo completo de un ticket

Ciclo de vida estándar
Desde la creación hasta el cierre con conformidad del cliente.
  1. Cliente crea el ticket → admins reciben email + WhatsApp
  2. Admin asigna al agente → agente recibe email + WhatsApp + notificación in-app
  3. Agente trabaja → intercambia mensajes con el cliente (ambos reciben email por cada respuesta)
  4. Admin marca como Resuelto → cliente recibe notificación in-app
  5. Cliente da conformidad → ticket pasa a Cerrado; admin/agente reciben notificación in-app
⚠️
Si el cliente no da conformidad, el ticket queda en estado Resuelto indefinidamente. Los admins pueden cerrarlo manualmente desde el panel de acciones o desde la vista de Conformidad en la gestión de tickets.
